# User Story — TIL Back-Office System

> แนวคิดหลัก: **"เข้าไว ซ่อมจบ ไม่ทำงานซ้ำ ติดตามงานได้แบบ Real time"**
> แอพจะต้องส่งเสริมแนวคิดนี้ในทุกฟีเจอร์

*(เอกสารนี้แปลงมาจาก `usestoryTIL.pdf` ต้นฉบับด้วยการดึงข้อความอัตโนมัติ ซึ่งตัวอักษรไทยบางส่วนในไฟล์ PDF ต้นฉบับถูกเข้ารหัสแบบสระ/วรรณยุกต์แยกจากพยัญชนะ ทำให้ข้อความที่ดึงออกมาโดยตรงผิดเพี้ยน ผู้แปลงได้เรียบเรียงข้อความให้ถูกต้องตามภาษาไทยโดยยึดเนื้อหาต้นฉบับเป็นหลัก โครงสร้าง/เลย์เอาต์ไม่จำเป็นต้องตรงกับต้นฉบับ)*

## แผนก SV

### 1. การรับงานจากลูกค้าของแผนก SV

ลูกค้าแจ้งงาน → ช่าง แจ้ง Admin ทางโทรศัพท์/ไลน์ → บันทึกงานลง Pool งาน SV เพื่อให้ทีม Admin ช่วยจัดการต่อ

### 2. การเปิด Task งานของทีม SV (กรณี Admin เปิดงานให้)

Admin คลิกที่ customer/project list เพื่อเลือกลูกค้า จะพบ customer machine list ที่เราขายให้ลูกค้าเจ้านี้ทั้งหมด เลือกเครื่องที่จะไปทำการตรวจเช็ก/ซ่อม เลือกหมวดที่จะตรวจเช็ก/ซ่อม เช่น ระบบไฟฟ้าและควบคุม, ระบบน้ำ, ระบบไอน้ำ, ระบบแก๊ส, ระบบลม, ระบบขับเคลื่อน, ระบบรองรับแรงสั่นสะเทือน, ระบบโครงสร้าง/ตะกร้าผ้า, ระบบทำความร้อน ฯลฯ

### 3. ช่างเปิดงานเอง (กรณีงานเพิ่มเติมที่ลูกค้าแจ้งเข้ามาระหว่างวัน/หน้างาน)

ช่างสามารถสแกน QR code ที่ติดอยู่หน้าเครื่องจักร เพื่อเลือกเปิดงานซ่อม เลือกหมวดที่จะตรวจเช็ก/ซ่อม เช่น ระบบไฟฟ้าและควบคุม, ระบบน้ำ, ระบบไอน้ำ, ระบบแก๊ส, ระบบลม, ระบบขับเคลื่อน, ระบบรองรับแรงสั่นสะเทือน, ระบบโครงสร้าง/ตะกร้าผ้า, ระบบทำความร้อน ฯลฯ

### 4. การเข้าทำงานและส่งงานของช่าง (ตามงานที่ Admin/ช่าง เปิดงานไว้)

ช่างสแกน QR code ที่หน้าเครื่อง ระบบจะลิงก์ข้อมูลที่ Admin เปิดงานมาให้ และแสดงให้ช่างเลือกว่าจะทำงานที่ Admin/ช่างเปิดไว้ หรือต้องการเปิดงานใหม่ (ในกรณีที่หน้างานแจ้งปัญหาเพิ่มเติม)

ช่างกดเลือกงานที่เปิดไว้ และบันทึกข้อมูลงานซ่อมลงใน Task ที่ได้รับมอบหมาย โดยบังคับลงรูป:
1. ใบงาน
2. อะไหล่เสียที่ตรวจพบ
3. อะไหล่ที่ทำการเปลี่ยนใหม่

### 5. หน้ารวม Task งานแผนก SV (หัวหน้าจะต้องสามารถดูภาพรวม Progress งานของแผนกได้)

งานทั้งหมดของทุกคนในแผนก SV ที่ได้รับมา รวมถึงงาน Office ที่ Admin/ช่างได้รับมา เช่น ทำป้าย, แปลคู่มือ, เทรนนิ่ง ฯลฯ จะต้องมารวมอยู่ใน Pool งานของแผนกด้วย (เพื่อป้องกันงานของแผนกตกหล่น และคนในแผนกช่วยกัน Monitor ได้) แต่จะแยกกลุ่มกับงานช่างว่าเป็นงาน Office SV หรือ งานช่าง (ลูกค้า)

และสามารถ:
- กำหนดผู้รับผิดชอบงานได้
- กำหนดวัน check point / deadline
- กำหนด Priority งาน
- แสดง Progress งานตาม workflow และอัพเดทสถานะของงานได้ เพื่อให้ติดตามสถานะของงานได้ เช่น ตรวจเช็ก → เสนอราคา → รอลูกค้าอนุมัติ (PO) → จัดเตรียมอะไหล่ (SO) → รอนัดลูกค้า → เข้าซ่อม → จบงาน

> ทุก Progress จะต้องมีวันที่ระบุ เพื่อให้ติดตามระยะเวลาในการทำงานได้ เพราะต้องการตั้ง KPI Mean Time to respond (MTTR) ในอนาคต

โดยสามารถค้นหา/เรียกดูได้ตาม: ชื่อลูกค้า / Serial number เครื่อง / Part number อะไหล่ / เลขที่ใบงาน / เลขที่ PO / เลขที่ SO

### 6. Pool Task งานเฉพาะบุคคล

สำหรับทุกคนในแผนก SV ใช้จัดการงานที่ได้รับมอบหมาย มีกำหนด Priority, Deadline, ส่งข้อมูลถามตอบในแผนก และ feedback ผ่าน online ได้เลย รวมถึงสามารถวิเคราะห์ Performance รายบุคคลและทำ Skill Matrix ได้เลย เพื่อให้การวัด KPI รายบุคคลและ Evaluations มีความชัดเจนและโปร่งใสขึ้น

### 7. ปฏิทินแสดง Task งานตามที่ได้รับมอบหมาย (ใช้วางแผนและจัดการงาน)

- งานภาพรวมของแผนก
- งานเฉพาะบุคคล

### 8. การค้นหา/รวบรวมประวัติเครื่องลูกค้า (รายเครื่อง / ทั้ง Project)

ใน customer machine list นี้เราสามารถเข้าไปดูประวัติการซ่อมทั้งหมดได้ และสามารถ export ข้อมูลออกมาได้ (ข้อมูลแต่ละงานต้องอยู่ใน Row เดียวกันทั้งหมด) ในกรณีที่ลูกค้าต้องการให้เราสรุปประวัติเครื่องจักรทั้งหมด เช่น

> "สรุปข้อมูลให้ผมทีว่าเครื่องตัวนี้ติดตั้งเมื่อไหร่ หมดประกันเมื่อไหร่ ซ่อม/เคลมอะไรไปบ้าง มูลค่าเท่าไหร่บ้าง"

โดยสามารถค้นหา/เรียกดูได้ตาม: ชื่อลูกค้า / Serial number เครื่อง / Part number อะไหล่ / เลขที่ใบงาน / เลขที่ PO / เลขที่ SO

### 9. ประวัติข้อมูลจำเพาะเครื่องจักร/ลูกค้า

ควรมีช่องให้บันทึกข้อมูลจำเพาะของลูกค้า เช่น:
- หมายเลขเครื่องหน้างาน
- ขนาดเพลากากบาท (กรณีเครื่องจีนเปลี่ยน Model แต่ไม่ได้แจ้ง)
- จำนวนโช๊คอัพ (กรณีดัดแปลง/เปลี่ยน Model)
- แผนที่
- ชื่อผู้ติดต่อและเบอร์โทร ได้แก่ House Keeping Manager, Laundry Manager, Laundry Supervisor, Laundry Worker (ถ้ามี), Chief Engineer, Chief Engineer Assistant, เลขาช่าง

รวมถึงมีช่องให้ Remark ข้อมูลที่แสดงถึง Character/Style/Customer Tier (Priority), ราชการ, VIP หรือข้อบังคับเฉพาะที่ลูกค้ากำหนดไว้ เพื่อให้ทีมงานทราบข้อมูลและเน้นย้ำทีมก่อนเข้าดำเนินการ

### 10. การตรวจสอบงานซ่อมซ้ำตาม KPI

**KPI: จำนวนซ่อมซ้ำของเครื่องจักรในปัญหาเดียวกันภายใน 3 วัน ≤ 1 เครื่อง/เดือน**

หาก Admin หรือ ช่าง เปิดงานและเลือกหมวดที่จะตรวจเช็ก/ซ่อม แล้วเครื่องจักร + หมวดปัญหา ซ้ำกันภายใน 3 วัน ระบบจะต้องแจ้งเตือน Service Manager / หัวหน้าช่าง / Admin เพื่อประเมินว่าเป็นเคสเดียวกันหรือไม่ หากใช่จะบันทึกเคสเพื่อสรุปผล KPI สิ้นเดือน

(ปัจจุบันไม่มีระบบแจ้งเตือน ทำให้การรวบรวมข้อมูลยาก ต้อง Export ข้อมูลงานตรวจเช็ก/ซ่อมทุกๆ สิ้นเดือน เพื่อให้หัวหน้าช่างประเมินและสรุปว่าแต่ละงานเป็นเคสเดียวกันหรือไม่ ซึ่งอาจทำให้การเก็บข้อมูลตกหล่นได้)

### 11. การค้นหาจำนวนคงเหลืออะไหล่

ช่างสามารถค้นหาจำนวนคงเหลืออะไหล่ได้ โดยค้นหาตาม Part number และมีรูปอะไหล่แสดงทุกรายละเอียดที่จำเป็นให้ครบถ้วน

### 12. การดำเนินงานและบันทึกงาน PM

ช่างสแกน QR code ที่หน้าเครื่อง ระบบจะลิงก์ข้อมูลงานที่เปิดไว้ เลือกทำ PM แสดง Form PM ที่ผ่านการวิเคราะห์และกำหนดขั้นตอนการทำ PM ตามลำดับ 1, 2, 3, 4 มาอย่างดีแล้ว (ป้องกันการทำงานข้ามไปข้ามมาสับสนและเสียเวลา) หากไม่ทำขั้นตอนนี้จะไม่สามารถผ่านไปขั้นตอนต่อไปได้

บังคับลงรูปในจุดที่จำเป็น เช่น รูปทำความสะอาด Before/After, การวัดกระแสไฟฟ้า, อัดจารบี ฯลฯ

### 13. การบันทึกงานลงระบบจากใบงานช่าง

มี AI ช่วยแปลง Photo to text เพื่อลดเวลาการพิมพ์ และให้ Admin ตรวจสอบข้อมูลให้ถูกต้องแทน

### 14. Performance Dashboard แผนก SV

เพื่อติดตามผลการดำเนินงานแบบ Real time ให้มากที่สุด เพื่อการปรับปรุงแก้ไขและพัฒนาระบบ/วิธีการทำงานให้ถูกต้อง แม่นยำ และรวดเร็วมากที่สุด

### 15. การสรุปข้อมูล

สรุปข้อมูล Part lifespan เฉลี่ยได้ เพื่อการวิเคราะห์อายุการใช้งานของอะไหล่แต่ละชนิด (สำหรับการปรับปรุงคุณภาพอะไหล่/ราคาอะไหล่ในอนาคต หรือใช้ตอบคำถามลูกค้า)

## ทีมติดตั้ง

### 16. การเบิกอุปกรณ์ติดตั้ง

ให้ระบบดึง Part ต่างๆ ตามแบบ Hook-up ที่ขึ้นทะเบียนไว้ได้เลย หากขาดอะไรให้ทีมติดตั้งเพิ่มรายการภายหลัง (ต้องการลดระยะเวลาในการเขียนรายการทั้งหมด เพราะมี Hook-up list ไว้หมดแล้ว)

## แผนก QC

### 17. งานตรวจรับเครื่องเข้าใหม่

- กรณีที่เครื่องเข้าใหม่ชำรุดต้องมีการซ่อม/ดัดแปลง QC สามารถลงงาน + รูป ไว้ใน Pool SV ได้
- มีบันทึก To do list สำหรับเครื่องเข้าใหม่จากจีน ที่ต้องมีรายการดัดแปลง/ทำเพิ่มเติม (ป้องกันการตกหล่น)

---

## แผนก ST

### 18. การแจ้งเตือนอะไหล่เข้าครบตาม SO

หาก ST ได้รับอะไหล่ครบถ้วนตาม SO ให้กดเปลี่ยนสถานะ และระบบจะแจ้งเตือนแผนก SV ว่าอะไหล่ตาม SO นี้ครบถ้วนแล้ว สามารถจ่ายงานช่างออกไปซ่อมให้ลูกค้าได้เลย

### 19. การจัดการ Stock อะไหล่ (ออฟฟิศภูเก็ต)

มีความจำเป็นที่ออฟฟิศที่ภูเก็ตจะต้องสำรองอะไหล่ไว้ให้ลูกค้า แต่ยังไม่มีบุคลากรและระบบที่ดีในการดำเนินงาน หากสามารถ:

- เบิกของและตัด Stock Online ผ่านแอพโดยใช้มือถือสแกน QR code ที่อะไหล่ หรือ
- ลงบันทึกในระบบเพื่อเบิกอะไหล่

โดยมีกำหนด Max-Min อะไหล่ และแจ้งเตือนให้เติมอะไหล่หากใกล้หมด
